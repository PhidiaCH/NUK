# NUKwork

## VPO 智慧幕僚系統 V0.4：落地版

V0.3 的問題不是「不夠聰明」，而是使用者不知道該在什麼時候、丟什麼資料、期待什麼輸出。因此 V0.4 改成以「工作流」而不是「功能清單」為核心：每一次使用都要能在 15 分鐘內產出可交付的決策素材。

## 產品定位

VPO（Virtual Project Officer）不是聊天機器人，而是專案負責人的智慧幕僚。它協助使用者把零散資訊整理成：

- 可決策的問題定義
- 可追蹤的行動清單
- 可同步的會議紀錄
- 可對齊的風險與取捨
- 可複用的專案知識庫

## V0.4 落地原則

1. **先做高頻場景，不做大全套平台**：優先支援每日站會、會議摘要、任務拆解、風險盤點、週報產出。
2. **輸入模板化**：使用者不需要想 prompt，只要貼上會議逐字稿、任務描述、文件片段或進度更新。
3. **輸出可直接複製**：每個結果都要能直接貼到 Slack、LINE、Notion、Jira、Email 或簡報。
4. **強制產出下一步**：每次回覆都必須包含 owner、deadline、status、risk。
5. **保留人工決策**：VPO 只提出建議與整理脈絡，不代替主管拍板。

## 建議先落地的 5 個工作流

| 工作流 | 使用時機 | 輸入 | 輸出 |
| --- | --- | --- | --- |
| 會議轉行動 | 會議後 5 分鐘內 | 逐字稿、會議筆記 | 決議、待辦、負責人、期限、風險 |
| 每日站會整理 | 每天早上 | 昨日完成、今日計畫、阻礙 | 團隊狀態摘要、阻塞清單、需要主管協助事項 |
| 任務拆解 | 接到新需求時 | 需求描述、限制、目標 | WBS、里程碑、驗收標準、風險 |
| 風險雷達 | 專案卡關或變更時 | 目前進度、問題、外部依賴 | 風險等級、影響、應對方案、升級條件 |
| 週報產生器 | 每週固定時間 | 本週進度、任務狀態、阻礙 | 對上週報、下週計畫、需決策事項 |

## 最小可行使用方式

1. 選一個工作流。
2. 把原始資料貼到對應模板。
3. 讓 VPO 產出第一版。
4. 使用者只做三件事：刪錯、補缺、確認 owner/deadline。
5. 把輸出貼到現有工具，不要求團隊更換系統。

## 使用者承諾

如果一次使用超過 15 分鐘還不能產出可交付內容，代表流程設計失敗，而不是使用者不會用。

詳細的導入 playbook 請見 [`docs/vpo-v04-playbook.md`](docs/vpo-v04-playbook.md)。

## 互動式原型

已新增一個可直接開啟的單頁互動原型：[`index.html`](index.html)。它把 VPO 落地成 VP Office 可操作的幕僚工作台，包含儀表板、會議記錄產生、AR 追蹤、報告上傳、達成率圖表、升遷路線圖與團隊分工。

### 本機預覽

```bash
python3 -m http.server 8000
```

啟動後打開 <http://localhost:8000/index.html>。
